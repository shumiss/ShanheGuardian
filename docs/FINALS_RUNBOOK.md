# 黔行守护决赛演示手册

## 一句话定位

黔行守护把游客需求、真实景区点位、天气和山地安全规则转化为可执行路线，并把每个风险继续推进到资源联动和处置闭环。

## 8 分钟主演示

1. 在游客端选择“亲子轻松游”，系统自动生成路线。
2. 切换第 1 天和第 2 天，说明地图点位、线路和风险摘要同步变化。
3. 点击黄果树或当日最高风险点，展示天气、地形、客流压力和服务覆盖证据。
4. 打开管理端“路线调度”，说明游客端路线已实时同步到运营侧。
5. 切到“安全指挥”，完成确认风险、分派服务资源、勾选现场动作和完成闭环。
6. 刷新页面，展示处置状态和记录仍然存在。
7. 打开“景区资源”，搜索贵州真实景区并纳入路线规划。
8. 最后只用一页架构图说明高德、公共数据、风险模型和 MindIE/vLLM Ascend 适配位置。

## 答辩口径

- 可以说：已实现高德天气、底图、道路规划适配和真实 POI 数据；当前网络可用时实时调用。
- 可以说：已实现 MindIE/vLLM OpenAI 兼容调用并通过模拟服务契约测试；接入真实昇腾地址后可切换。
- 必须说：当前客流为压力指数估算，不是景区实时人数。
- 必须说：贵州数据集中心当前接入目录，正式数据内容仍需赛事账号授权。
- 不要说：系统已经接入全省实时游客人数、正式票务或全部公共数据内容。

## 现场检查

1. 访问 `/api/health`，确认版本为 `2026.07-finals-p1`。
2. 游客端和管理端各打开一个窗口。
3. 先生成一次两天路线，确认两个日期标签都可切换。
4. 确认地图左上角显示“高德驾车道路”或诚实显示“点位关系示意”。
5. 预先完成一条安全事件，确认刷新后能够恢复。
6. 网络不稳定时保留本地规则模型，不在现场反复点击接口检测。
